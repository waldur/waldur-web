Integrations & add-ons

Waldur supports integration with various private and public cloud services for delivering of additional functionality. The list of currently supported integrations is below. New services are integrated following business demand and can be delivered specifically for your deployment. Contact us to find out more!

Harbor

Harbor is an open-source container image registry that secures artifacts with policies and role-based access control. Waldur integrates with Harbor to provide self-service management of container registry projects through the marketplace, enabling teams to request and manage their own registries with proper access control.
Documentation

Kubernetes namespaces

Kubernetes isolates teams in namespaces with their own quotas and access rights. On a cluster the provider runs, the Waldur Site Agent turns marketplace orders into namespaces with CPU, memory and storage quotas, through a ManagedNamespace custom resource that an operator in the cluster acts on. It keeps the namespace’s Keycloak groups in line with Waldur membership, enforces pause and downscale through the quota, and can bill each namespace by the consumption Prometheus measured. Running the cluster stays with the provider.
Documentation

NetBox

NetBox is an open-source source of truth for network and infrastructure inventory (DCIM/IPAM). The Waldur NetBox exporter, a standalone service in its own repository, mirrors OpenStack inventory managed by Waldur into NetBox as a read-only, tagged copy: customers and projects become tenant groups and tenants, OpenStack tenants become clusters, instances become virtual machines with their interfaces, IP addresses and floating IPs, and VLAN networks and subnets map to VLANs and prefixes. Changes follow Waldur’s event stream within seconds, with periodic reconciliation as a safety net, and the mirror can be limited to selected offerings. Manually created NetBox records are never touched. It writes through the NetBox REST API, or through NetBox Labs’ Diode for scheduled full syncs.
Documentation

OKD/OpenShift

OKD is the community distribution of Kubernetes that powers Red Hat OpenShift. On a cluster the provider runs, the Waldur Site Agent turns marketplace orders into OpenShift projects with a resource quota from the ordered limits, grants project members access through role bindings, and reports the quota’s current usage. Pausing or downscaling a resource lowers the quota, and terminating it deletes the project.
Documentation

Rancher Kubernetes clusters

Rancher is a platform for deploying and operating Kubernetes clusters. Waldur creates Kubernetes clusters through Rancher on virtual machines in the customer’s OpenStack tenant: an order sets up the tenant’s network and security groups, starts the server and agent nodes, and registers the cluster in Rancher. Customers keep control of the cluster’s virtual machines, while the provider runs Rancher and maps Waldur roles onto Rancher roles through Keycloak groups.
Documentation

Rancher projects

On Rancher clusters that a provider already runs, the Waldur Site Agent turns marketplace orders into Rancher projects with CPU, memory and storage quotas, reports their quota usage, and keeps Keycloak groups bound to the project roles in line with Waldur membership. Alternatively, the agent only describes each project and its members as a Kubernetes custom resource, and the Rancher Keycloak operator running in the cluster creates the Rancher project and the Keycloak group bindings, so Rancher and Keycloak credentials stay in the cluster.
Documentation

Waldur-to-Waldur Federation

Waldur supports federation between multiple Waldur instances, allowing organizations to share and consume offerings across independent deployments. This enables cross-organizational resource sharing and collaborative service delivery while maintaining separate governance domains, with automated synchronization of offerings and orders between instances.
