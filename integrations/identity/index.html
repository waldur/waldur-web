Integrations & add-ons

Waldur supports integration with various private and public cloud services for delivering of additional functionality. The list of currently supported integrations is below. New services are integrated following business demand and can be delivered specifically for your deployment. Contact us to find out more!

eduGAIN

eduGAIN is a federated academic identity service connecting research and education institutions worldwide. Waldur supports full integration as an eduGAIN Service Provider, including CoCo extensions for higher security guarantees. Users authenticate via their home organization credentials while maintaining federated identity attributes.
Documentation
eduTEAMS

eduTEAMS

eduTEAMS is GÉANT’s identity and access management service for research collaborations. Waldur supports eduTEAMS as an OpenID Connect identity provider. A user’s community identifier is stored as their Waldur username, so their permissions can be looked up by it.
Documentation
FreeIPA

FreeIPA

Waldur synchronises users, organizations and projects into FreeIPA: organizations and projects become FreeIPA groups, and memberships follow Waldur roles. Users who sign in through federated identity providers such as eduGAIN get Linux accounts for services like Slurm without manual administration.
Documentation

GLAuth

GLAuth is a lightweight LDAP server. Waldur renders a complete GLAuth configuration from marketplace identities: offering users and robot accounts become LDAP accounts, with role-aware groups derived from Waldur project and resource permissions. POSIX UID and GID values are allocated from per-provider pools, so a user keeps a single consistent UID across every offering that resolves to the same pool.
Documentation

Keycloak

Keycloak is an open-source identity and access management server. Users sign in to Waldur through Keycloak over OpenID Connect, which also puts Waldur behind the same single sign-on as a site’s other services. On the provider side, the Waldur Site Agent keeps Keycloak groups in line with Waldur membership for the Rancher, Kubernetes namespace and OpenNebula integrations, and the Rancher Keycloak operator does the same inside a Rancher cluster, so access to those services follows the roles people hold in Waldur.
Documentation

LDAP

Waldur supports taking user identities from an external LDAP-server, such as FreeIPA, OpenLDAP or Active Directory. Simple configuration for LDAP schema allows connecting existing user profiles with Waldur for authentication. This enables organizations to use their existing directory infrastructure as the identity source for Waldur.
Documentation

LDAP account provisioning

For systems that take their accounts from LDAP, such as HPC clusters, the Waldur Site Agent writes to the directory: it creates POSIX accounts and groups for the members of an offering, keeps their profiles up to date and releases the accounts when people leave. Roles on Waldur resources and projects can also be mapped onto LDAP group memberships, so access to a system follows the roles assigned in Waldur.
Documentation
Entra ID

Microsoft Entra ID

Microsoft Entra ID, formerly Azure AD, is Microsoft’s cloud identity service. Waldur signs users in with their Entra ID accounts over OpenID Connect, with Waldur registered as an application in the organization’s Entra tenant. Claims from Entra ID, such as name, email address and username, fill in the user’s Waldur profile.
Documentation

MyAccessID

MyAccessID is GEANT’s identity service for research infrastructures. Waldur integrates with MyAccessID enabling Infrastructure Service Domains to push user attributes with per-attribute source tracking across multiple domains. It supports multi-ISD lifecycle management ensuring user data integrity when one domain’s access is revoked while others remain active.
Documentation

ORCID

ORCID gives researchers a persistent identifier. Reviewers in Waldur’s calls for proposals connect their ORCID iD to their reviewer profile and import their affiliations and publications from it, and publications added by DOI are completed from Crossref. The profile feeds reviewer matching and conflict-of-interest checks, such as co-authorship with applicants.
Documentation

Passkeys (FIDO2/WebAuthn)

Passkeys give phishing-resistant sign-in without an external identity provider. Users can sign in with a passkey instead of a username and password, or use one as a second factor after their password. They are meant for deployments without a federated identity provider, and for staff accounts everywhere, and are off until the operator turns them on.
Documentation

SAML

Waldur supports federated identity providers over SAML 2.0 protocols with configurable identity providers and attribute mapping. It enables Single Sign-On authentication with signed requests, encrypted assertions, and metadata exchange. Automated account creation and updates are driven by information from SAML attributes during authentication flows.
Documentation
SRAM

SRAM

SRAM (SURF Research Access Management) manages research collaborations. SRAM pushes collaborations, their members and groups to Waldur’s SCIM 2.0 endpoint, and rules configured in Waldur decide what access they grant.
Documentation
TARA

TARA

TARA is the Estonian state authentication service. Waldur supports TARA as an identity provider, so users can sign in with national electronic identity: ID card, Mobile-ID or Smart-ID.
Documentation

Waldur DB

Waldur provides built-in user profile management within its local database, requiring no additional identity infrastructure. Profile fields can be tuned to match deployment specifics, including support for additional names in national languages. This is the simplest identity option, suitable for standalone deployments without external identity providers.
